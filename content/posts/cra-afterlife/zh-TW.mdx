很多 React 教學曾經都從同一行指令開始：`npx create-react-app`。所以 CRA 正式退場時，第一個反應很容易是「那現在官方指定大家用什麼？」答案其實沒有那麼整齊。

Create React App 曾經是建立 React 專案最省事的方法，但它後來缺少積極維護，建置速度和現代工具也逐漸跟不上。React 官方因此在 2025 年正式把它標成 deprecated。

如果原本做的是登入後台或一般 SPA，Vite 通常就是最直接的接班人。它負責啟動開發環境和打包程式，路由、資料請求仍由我們自己選。Next.js 則多了檔案路由、伺服器渲染、靜態產生和後端功能，並不是每個 React 專案都需要。

簡單說，CRA 退場並不等於大家都要改用 Next.js。先看網站需要什麼：單純 SPA 可以從 Vite 開始；內容網站、電商或需要 SSR 的頁面，再考慮 Next.js 或其他 React framework。

## Vite 和 Next.js 其實不是同一層

Vite 主要是建置工具，它把開發伺服器、HMR 和 production build 準備好。路由可以選 React Router，資料請求可以用原生 fetch、TanStack Query 或其他方案。自由度很高，代價是專案規模變大後，這些選擇要由團隊自己整理。

Next.js 則先幫你決定不少事情：目錄就是路由、頁面可以在伺服器產生、Metadata 和圖片處理也有官方做法。這對公開網站很方便，但若只是公司內部後台，導入整套伺服器模型未必比較省事。

SSR 也不只是 SEO。伺服器先送出 HTML，慢一點的手機通常能更早看到內容；但伺服器要多做工作，部署和快取也會複雜一些。若頁面登入後才看得到，搜尋引擎根本不是重點，CSR 往往已經很夠用。

所以我會把問題改成「這個專案只缺一個新的 CRA，還是已經需要完整框架？」前者選 Vite 很合理；後者才需要看 Next.js、React Router framework mode 等方案。
