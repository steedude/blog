Astro 6 才剛讓內容網站的工作流程更完整，7 又把焦點拉回編譯器。版本走得快不代表每次都要追著搬家，這次比較值得問的是：底層換成 Rust，寫 MDX 的人究竟會感受到什麼？

Astro 7 把更多編譯工作交給 Rust，包括內容網站常用的 Markdown 和 MDX。對使用者來說，不需要先學 Rust，原本的文章格式也沒有因此消失。

這次更新的重點比較像底層整理：搭配 Vite 8、加快內容處理，也替更複雜的 routing 情境補上能力。網站文章愈多，建置流程是否有效率就愈容易被注意到。

如果只是幾十篇文章的小部落格，不必因為 Rust 就立刻搬家。Astro 7 比較值得關注的是，它仍然把內容網站當成主要使用情境，而不是急著把所有全端功能都塞進來。

MDX 使用者可能會更在意相容性：語法能不能照舊、remark/rehype plugin 是否正常、錯誤訊息看不看得懂。底層換語言對使用者應該愈無感愈好，速度只是結果，遷移時不必改文章才是真正舒服的升級。

如果網站主要內容是 Markdown，升級前備份和固定 plugin 版本就很重要。編譯器換掉後，最可能出現差異的是少見語法或 plugin 串接，不是一般標題和段落。先看官方 migration note，再處理個別例外即可。
