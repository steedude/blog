「我們支援現代瀏覽器就好。」我每次聽到這句都很想追問：所以 Safari 16 算現代嗎？公司那台三年沒更新的 Windows 呢？大家講的時候都懂，真的要寫進規格就突然沒人能給版本。Vite 7 改用 Baseline 讓我覺得有點鬆一口氣，至少這場對話終於有一條不完全靠感覺的起跑線。

Vite 7 把 production build 的預設瀏覽器目標改成 Baseline Widely Available。名字有點長，概念其實不複雜：選擇已經在主要瀏覽器普遍存在一段時間的 Web 功能，當成預設支援範圍。

Baseline 的 Newly Available 代表主要瀏覽器都已支援；再經過 30 個月，才會成為 Widely Available。Vite 7 因此有了一條比較清楚的支援界線，而不是只說「支援現代瀏覽器」。

這項設定主要影響打包後的 JavaScript 語法，並不會自動替所有缺少的 Web API 加上 polyfill。如果網站有公司內部舊電腦或特殊裝置使用者，仍應依自己的使用者環境調整。

## Vite 7 實際選了哪些版本？

這個 major release 對應到 Chrome 107、Edge 107、Firefox 104 和 Safari 16。以後 Vite major 更新時，這份清單也會跟著當時的 Widely Available 範圍往前移。好處是預設值有一個共同規則，而不是由維護者憑感覺挑版本。

但 Baseline 不是專案的產品需求。銀行內部系統和只給新手機使用的活動頁，理所當然會有不同支援範圍。Vite 提供的是合理預設，最後還是要看網站流量、公司規範和功能能不能漸進增強。

比較務實的做法，是把實際流量裡的瀏覽器版本、錯誤監控和產品承諾放在一起看。若真的要照顧舊環境，就挑出核心流程做真機或雲端瀏覽器測試，不要只相信 build 沒報錯。Baseline 解決的是大家如何描述共同起點，並沒有替每個網站做完相容性測試。
